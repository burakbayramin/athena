<task type="auto" tdd="true">
  <name>Task 1: AgentError enum and CircuitBreaker state machine</name>
  <files>crates/ath-agents/src/error.rs, crates/ath-agents/src/circuit_breaker.rs</files>
  <behavior>
    - AgentError has variants: RateLimit, AuthFailed, ServerError, Timeout, InvalidResponse, CircuitOpen, ActorStopped, Unknown
    - is_retryable() returns true for RateLimit, ServerError, Timeout, InvalidResponse; false for AuthFailed, CircuitOpen, ActorStopped, Unknown
    - CircuitBreaker starts in Closed state with 0 consecutive failures
    - can_attempt() returns true in Closed state
    - After 3 consecutive record_failure() calls, can_attempt() returns false (Open state)
    - record_success() resets to Closed with 0 failures from any state
    - After cooldown (30s), can_attempt() returns true once (HalfOpen), then false until success or cooldown again
    - In HalfOpen, record_failure() reopens the circuit (resets cooldown timer)
    - In HalfOpen, record_success() closes the circuit
  </behavior>
  <action>
Create `crates/ath-agents/src/error.rs`:
- Define `AgentError` enum using `thiserror::Error` exactly as specified in RESEARCH.md code example. All variants carry `provider: String` except `ActorStopped`. `RateLimit` has `retry_after: Option<Duration>`. `ServerError` has `status: u16`. `Timeout` has `duration: Duration`. `InvalidResponse` and `AuthFailed` have `reason: String`. `Unknown` has `source: String`.
- Implement `is_retryable()` -- RateLimit, ServerError, Timeout, InvalidResponse are retryable. Everything else is not.
- Derive Debug, but NOT Clone (thiserror 2.0 errors don't need Clone for our use case -- they flow through Result, not stored in collections).

Create `crates/ath-agents/src/circuit_breaker.rs`:
- Define `CircuitState` enum: `Closed { consecutive_failures: u32 }`, `Open { opened_at: tokio::time::Instant }`, `HalfOpen`.
- Define `CircuitBreaker` struct with `state: CircuitState`, `failure_threshold: u32` (default 3), `cooldown: Duration` (default 30s).
- Use `tokio::time::Instant` (not `std::time::Instant`) so tests can use `tokio::time::pause()` for deterministic time control.
- Implement `CircuitBreaker::new(failure_threshold, cooldown)` and `CircuitBreaker::default()` (3 failures, 30s).
- Implement `can_attempt(&mut self) -> bool` -- Closed: true; Open: check cooldown, transition to HalfOpen if elapsed, return true; HalfOpen: false (probe in flight).
- Implement `record_success(&mut self)` -- any state -> Closed { consecutive_failures: 0 }.
- Implement `record_failure(&mut self)` -- Closed: increment, trip if >= threshold; HalfOpen: reopen with fresh cooldown; Open: no-op.
- Implement `is_open(&self) -> bool` for external status checking.

Write inline `#[cfg(test)]` modules in both files. Circuit breaker tests MUST use `#[tokio::test(start_paused = true)]` and `tokio::time::advance()` for deterministic cooldown testing.
  </action>

  </verify>
