    - Test 5: Feedback from most recent rejection is injected into retry (not accumulated history)

  <action>
    Add to phase_runner.rs:

    Implement the main orchestration function:
    ```
    pub async fn run_phase(
        phase: &PhaseSpec,
        registry: &AgentRegistry,
        available: impl Fn(&AgentKind) -> bool,
        write_files: impl Fn(&[FileOutput]) -> Result<(), PhaseRunnerError>,
        git: Option<&AsyncGitLayer>,
    ) -> Result<PhaseRecord, PhaseRunnerError>
    ```

    Logic using the typestate machine:
    1. Create PhaseState::new(phase.id, phase.name.clone()) -- starts as Pending
    2. Select reviewer via review::select_reviewer(task_agents, phase.name, available). Cache result for all attempts per user decision.
    3. Transition Pending -> Running via .start()
    4. Execute tasks via execute_phase_tasks(phase, registry, None)
    5. Transition Running -> AwaitingReview via .submit_for_review(outputs, 1)
    6. Build review prompt via review::build_review_prompt
    7. Create review AgentRequest with review_verdict_schema, dispatch to reviewer backend
    8. Parse verdict via review::parse_review_verdict

    9. If verdict.passed:
       - Transition AwaitingReview -> Complete via .approve()
       - Call write_files with all FileOutputs from all task outputs
       - If git is Some, call commit_phase_async with CommitMetadata
       - Build and return PhaseRecord

    10. If verdict fails:
        - Call .reject(verdict) which returns RejectOutcome
        - If Retry(retrying_state):
          - Record ReviewAttempt in PhaseRecord audit trail
          - Transition Retrying -> Running via .retry()
          - Re-execute tasks with execute_phase_tasks(phase, registry, Some(&verdict))
          - Loop back to step 5 with new attempt number
        - If Failed(failed_state):
          - Record final ReviewAttempt
          - Return PhaseRunnerError::MaxRetriesExceeded

    Per user decision:
    - Always use all 3 attempts, no early bail
    - Feedback injection: most recent attempt only
    - Files written only after review passes
    - Same reviewer across all attempts

    For testing: use MockBackend for both task agents and reviewer. The reviewer MockBackend returns sequenced responses (fail, fail, pass) to test retry behavior. write_files is a closure that captures a Vec<FileOutput> for verification. git is None in unit tests.
