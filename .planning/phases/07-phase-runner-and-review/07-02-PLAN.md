    - Test 2: Single Gemini-authored phase selects Claude as reviewer (highest priority non-author)
    - Test 3: Multi-author phase (2 Claude tasks, 1 Gemini task) excludes Claude (majority) and selects Gemini
    - Test 4: Multi-author phase with tie (1 Claude, 1 Gemini) excludes Claude (priority tiebreak) and selects Gemini
    - Test 5: When preferred reviewer circuit breaker is tripped, falls back to next eligible non-author
    - Test 6: When ALL non-author agents unavailable, returns NoReviewerAvailable error
    - Test 7: Codex-only phase with Claude unavailable selects Gemini
  </behavior>
  <action>
    Create crates/ath-orchestrator/src/review.rs.

    Define a ReviewError enum with thiserror:
    - NoReviewerAvailable { phase_name: String, reason: String }

    Implement select_reviewer function:
    ```
    pub fn select_reviewer(
        task_agents: &[AgentKind],
        phase_name: &str,
        available: impl Fn(&AgentKind) -> bool,
    ) -> Result<AgentKind, ReviewError>
    ```

    Logic per user decisions:
    1. Count tasks per agent using std::mem::discriminant (same pattern as router.rs)
    2. Find majority author. On tie, pick the one with higher priority (Claude > Gemini > Codex) as "majority" to exclude
    3. Iterate candidates in priority order: Claude, Gemini, Codex
    4. Skip majority author's discriminant
    5. For each candidate, check available(). Return first available.
    6. If none available, return NoReviewerAvailable error

    Use default model strings for candidate construction: Claude("opus-4"), Gemini("2.5-pro"), Codex("o3") -- these are just for discriminant matching; actual model selection happens at dispatch time.

    Per user decision: same reviewer across all retry attempts. The caller (PhaseRunner) is responsible for caching the selected reviewer -- this function is pure selection logic.
  </action>
  <verify>
    <automated>cargo test -p ath-orchestrator review::tests -x</automated>
  </verify>
  <done>select_reviewer correctly excludes majority author, respects priority order, handles circuit breaker fallback, and returns clear error when no reviewer is available. All 7 test cases pass.</done>
</task>
