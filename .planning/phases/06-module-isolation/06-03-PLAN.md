  <name>Task 1: Pre-dispatch file ownership check across parallel phases</name>
  <files>crates/ath-orchestrator/src/isolation.rs</files>
  <behavior>
    - check_isolation on plan with parallel phases having disjoint files returns Ok(())
    - check_isolation on plan with parallel phases having overlapping file returns FileConflict error
    - check_isolation allows same file in sequential phases (different parallel groups)
    - check_isolation allows same file across tasks within one phase (sequential execution)
    - FileConflict error identifies the file, both task names, and both phase IDs
    - FileConflict hint says "Split into separate phases or consolidate into one task"
    - Plan with single-phase parallel groups always passes (no conflict possible)
    - Plan with empty parallel_groups passes
  </behavior>
  <action>
Create crates/ath-orchestrator/src/isolation.rs:

1. Implement `pub fn check_isolation(plan: &ExecutionPlan) -> Result<(), IsolationError>`:
   - For each parallel_group in plan.parallel_groups:
     - Build HashMap<String, (u32, String)> mapping file path -> (phase_id, task_name)
     - For each phase_id in the group, find the PhaseSpec by id
     - For each task in the phase, for each file in expected_output_files:
       - If file already in ownership map from a DIFFERENT phase, return FileConflict error
       - If same phase (sequential tasks), allow -- just update/skip (per decision: sequential overlap within phase allowed)
       - Otherwise insert into ownership map
   - Return Ok(()) if no conflicts found

Key design points per user decisions:
- Exact file path matching only -- no directory-level overlap detection
- Cross-phase conflict checking only applies to phases within the same parallel group
- Within a single phase, tasks execute sequentially and CAN share files (Pitfall 3)

2. Add `pub mod isolation;` to lib.rs.

Write #[cfg(test)] module with helper functions to build test ExecutionPlans. Test all behavior cases above.
