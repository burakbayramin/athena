  <name>Task 1: route_task with majority vote, tiebreak, and fallback</name>
  <files>crates/ath-orchestrator/src/router.rs</files>
  <behavior>
    - route_task with tags ["rust", "api"] returns Claude (1 Claude + 1 Gemini, Claude wins tiebreak)
    - route_task with tags ["rust", "logic", "api"] returns Claude (2 Claude vs 1 Gemini)
    - route_task with tags ["docs", "research", "api"] returns Gemini (3 Gemini)
    - route_task with tags ["codegen", "boilerplate"] returns Codex (2 Codex)
    - route_task with empty tags returns Claude (default)
    - route_task with tags ["unknown1", "unknown2"] returns Claude (no matches, default)
    - route_task where best agent is unavailable falls back to next-best
    - route_task where all agents unavailable returns AllAgentsUnavailable error
    - RoutingDecision.rationale contains human-readable explanation of why agent was chosen
    - Discriminant-based vote counting: Claude("opus-4") and Claude("sonnet-4") count as same provider
  </behavior>
  <action>
Create crates/ath-orchestrator/src/router.rs:

1. Define `RoutingDecision` struct with `agent: AgentKind` and `rationale: String`.

2. Implement `pub fn route_task(skill_tags: &[SkillTag], table: &HashMap<String, AgentKind>, available: impl Fn(&AgentKind) -> bool) -> Result<RoutingDecision, IsolationError>`:
   - If skill_tags is empty, return default_agent() with rationale "No skill tags; defaulting to Claude"
   - Count votes per agent kind using `std::mem::discriminant()` for variant-only comparison (avoids model string fragmentation per Pitfall 4)
   - Normalize tags to lowercase before lookup (per Pitfall 2)
   - Sort candidates by (vote_count desc, priority asc)
   - Pick first candidate that passes available() check
   - If no tags match table, return default_agent() with rationale "No matching skill tags; defaulting to Claude"
   - If all candidates fail available(), return IsolationError::AllAgentsUnavailable with provider names and hint "Check API keys and provider quotas"
   - Build rationale string: "Tags [rust, logic] -> Claude (2 votes), Gemini (0 votes), Codex (0 votes)"

3. Add `pub mod router;` to lib.rs (if not already present from Plan 01 -- Plan 01 only added error and taxonomy).

Write #[cfg(test)] module with tests for all behavior cases above. Use closure `|_| true` for all-available and targeted closures for fallback/unavailable tests.
