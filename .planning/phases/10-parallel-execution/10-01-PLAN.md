  <action>
Refactor `run_plan_with_progress` to iterate `plan.parallel_groups` instead of `plan.execution_order`. The method signature stays identical.

**Step 1: Pre-dispatch isolation check.** At the top of `run_plan_with_progress`, call `crate::isolation::check_isolation(plan)` and map `IsolationError` to `PhaseRunnerError::IsolationViolation { details: e.to_string() }`. This catches file conflicts before any LLM call.

**Step 2: Create commit gate.** `let commit_gate = Arc::new(tokio::sync::Mutex::new(()));` shared across all parallel tasks within a group.

**Step 3: Iterate parallel_groups.** Replace the `for (phase_index, &phase_id) in plan.execution_order.iter().enumerate()` loop with:

```rust
for (group_index, group) in plan.parallel_groups.iter().enumerate() {
    if group.len() == 1 {
        // Single-phase group: run directly (no spawn overhead)
        // Reuse the existing sequential logic for this single phase
        // phase_index = sum of all prior group sizes + 1
    } else {
        // Multi-phase group: JoinSet fan-out
    }
}
```

**Step 4: Single-phase group path.** For `group.len() == 1`, extract the phase, emit PhaseStarted/PhaseCompleted, call `run_phase_with_progress`, write files, git commit -- exactly as the current sequential loop does. Compute `phase_index` as the cumulative count of phases processed so far plus 1.

**Step 5: Multi-phase group path.** For `group.len() > 1`:
- Create a `tokio::task::JoinSet<Result<(u32, String, PhaseRecord), PhaseRunnerError>>` where the tuple is `(phase_id, phase_name, record)`.
- For each `phase_id` in the group, clone `Arc`-wrapped references needed by the spawned task:
  - The registry needs to be accessible. Since `AgentRegistry` is not `Clone`, wrap `&self.registry` access via an `Arc`. Store `Arc<AgentRegistry>` in the coordinator struct (change `registry: AgentRegistry` to `registry: Arc<AgentRegistry>`) OR keep the current design and use a scoped approach. **Preferred approach:** Change `AgentCoordinator.registry` field type from `AgentRegistry` to `Arc<AgentRegistry>`, and update `new()` to accept `AgentRegistry` and wrap it. This is a non-breaking change since callers pass ownership. The `run_plan_with_progress` sequential path uses `&*self.registry` unchanged.
  - Clone `commit_gate: Arc<tokio::sync::Mutex<()>>`
  - Clone `observer: Option<SharedProgressObserver>` (already Arc-based)
  - Clone `self.output_dir` (PathBuf, cheap)
  - Clone `self.git` -- `AsyncGitLayer` needs to be cloneable. Check if it implements Clone; if not, wrap in `Arc<Option<AsyncGitLayer>>`. **Note:** `AsyncGitLayer` wraps `Arc<GitLayer>` internally, so it should be Clone already. Verify and use `.clone()`.
- In each spawned task:
  1. Emit `ProgressEvent::PhaseStarted` (use group_index-based phase_index -- all phases in the group share the same group position)
  2. Call `run_phase_with_progress(phase, &registry, available, write_files_fn, git, observer)`
  3. After the phase completes, acquire `commit_gate.lock().await`
  4. Write files to `output_dir` (same `write_files` closure logic as current code)
  5. Git commit if configured
  6. Drop the guard
  7. Emit `ProgressEvent::PhaseCompleted`
  8. Return `Ok((phase_id, phase_name, record))`
- Collect results from `set.join_next().await`:
  - Map `JoinError` to `PhaseRunnerError::ParallelPhaseFailed { phase_name: "unknown".into(), reason: e.to_string() }`
  - On first `Err` from any phase, call `set.abort_all()` (fail-fast, matching existing sequential behavior), then return the error
  - Collect successful `(phase_id, phase_name, record)` tuples
- Sort collected tuples by `phase_id` before extending `results` vec (deterministic ordering per research recommendation)

**Step 6: Handle the `write_files` closure.** The current closure captures `self.output_dir` by move. For parallel dispatch, each spawned task needs its own closure. Create the `write_files` closure inside the spawned task body using the cloned `output_dir`. The closure logic is identical to the current implementation.

**Step 7: Handle the `available` closure.** The `available` closure checks `self.registry.get(kind).is_some()`. With `Arc<AgentRegistry>`, clone the Arc and create the closure inside the spawned task.

**Important constraints:**
- Do NOT use `std::sync::Mutex` across await points -- use `tokio::sync::Mutex` for the commit gate.
- Do NOT hold the commit gate during LLM execution -- only during write_files + git commit.
- Do NOT modify `run_phase_with_progress` signature or `phase_runner.rs` at all.
- Preserve all existing test helpers and tests in the `#[cfg(test)]` module. Update `make_plan` helper if needed to populate `parallel_groups` for existing tests (single-phase groups matching `execution_order`). For example, `make_plan(vec![phase1, phase2], vec![1, 2])` should also set `parallel_groups: vec![vec![1], vec![2]]` so existing sequential tests exercise the single-phase-group path.
- After implementation, the 4 Wave 0 test stubs from plan 00 should no longer panic at todo!() -- they should exercise the new parallel paths. The stubs will still fail (they assert specific behaviors that need the full test body from plan 02), but they should no longer panic at the `todo!()` line if the `todo!()` is unreachable due to the setup calling `run_plan` which now exercises parallel groups.
