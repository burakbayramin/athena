    **validate.rs**: Create DAG structural validation.

    ```rust
    pub enum PlanWarning {
        LargePhase { phase_id: u32, phase_name: String, task_count: usize },
        LongCriticalPath { length: usize },
    }
    ```

    `pub fn validate_plan(phases: &[PhaseSpec], project: &ProjectSpec) -> Result<Vec<PlanWarning>, Vec<ValidationError>>`:
    1. Collect hard errors into a Vec<ValidationError>:
       a. Empty phases: any phase with tasks.is_empty()
       b. Missing dependency targets: for each phase, each depends_on ID must exist in the phase list
       c. Circular dependencies: call topological_sort -- if Err, create CircularDependency error with the cycle path formatted as "1 -> 3 -> 1"
       d. Orphaned goals: for each goal index in 0..project.goals.len(), at least one TaskSpec across all phases must have that index in goal_indices
       e. Unsatisfied contracts: for each phase, each consumed contract must be produced by some phase in the transitive dependency closure. Compute transitive closure from the depends_on edges (BFS from each phase's direct deps, collecting all reachable produces).
    2. If errors is non-empty, return Err(errors).
    3. Collect warnings:
       a. LargePhase: any phase with >5 tasks
       b. LongCriticalPath: if critical_path_length > 7
    4. Return Ok(warnings).

    Note: validate_plan calls `topological_sort` from dag.rs for cycle detection and `critical_path_length` from dag.rs for warning computation. Import both.

    **prompt.rs**: LLM decomposition prompt and schema.

    `pub fn execution_plan_json_schema() -> serde_json::Value`: JSON schema matching the PhaseSpec structure (phases array only -- execution_order/parallel_groups/critical_path_length are computed server-side). Follow the schema from RESEARCH.md exactly.

    System prompt constant `DECOMPOSE_SYSTEM_PROMPT`: Instruct Claude to decompose a ProjectSpec into phases. Include rules:
    - Generate 3-10 phases (soft bound)
    - Each phase: id (sequential starting from 1), name, description, 2-5 tasks, depends_on (IDs of prerequisite phases), produces, consumes
    - Each task: name, description, skill_tags (plain strings), expected_output_files, acceptance_criteria, goal_indices (referencing ProjectSpec goals by 0-based index)
    - Every goal must be covered by at least one task
    - Dependencies must be acyclic
    - Each consumed contract must be produced by a dependency
    - Respond with valid JSON matching the schema

    `pub fn build_decompose_request(project: &ProjectSpec, last_error: Option<&str>) -> AgentRequest`:
    - system: DECOMPOSE_SYSTEM_PROMPT
    - user: Serialize project as JSON. If last_error is Some, append: "\n\nYour previous attempt had errors:\n{last_error}\n\nPlease fix these issues and try again."
    - Set json_schema to Some(execution_plan_json_schema())
    - Use AgentKind::Claude("decompose".into()), new UUID, Utc::now()

    Update **mod.rs** to add: `pub mod validate; pub mod prompt;`
