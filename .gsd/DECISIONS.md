# Decisions

<!-- Append-only register of architectural and pattern decisions -->

| ID | Decision | Rationale | Date |
|----|----------|-----------|------|
| D001 | Use `hnswlib-rs` (v0.10) for vector index | Pure Rust, no C/C++ deps, cross-platform, persistence API, cosine metric, string keys, incremental insert/delete. `corenn-kernels` dependency is also pure Rust (only depends on `half`). | 2026-03-14 |
| D002 | Keyword fallback via simple inverted index (HashMap-based) | At Athena's scale (~1000 entries), a hand-rolled TF-IDF index is sufficient. Avoids `tantivy` dependency weight. JSON-serialized for simplicity. | 2026-03-14 |
| D003 | Viking Store uses markdown files (not JSON) for content persistence | Human-readable format lets users inspect and manually edit memory entries. L0/L1/L2 stored as markdown sections with YAML frontmatter for metadata. | 2026-03-14 |
| D004 | MemoryIndex uses `meta.json` alongside binary index files | Stores dimension, entry count, timestamps. Enables dimension mismatch detection on reload and provides an inspection surface for diagnostics. | 2026-03-14 |
| D005 | Store markdown parser splits only on known section headings (`## Abstract`, `## Overview`, `## Detail`) | User content within sections may contain its own `##` headings (e.g., overview_text with `## Conventions`). Splitting on all `## ` lines would break round-trip fidelity. | 2026-03-14 |
| D006 | Use `hnsw` crate (v0.11) instead of `hnswlib-rs` (v0.10) for vector index | `hnswlib-rs` depends on `off64` which uses `std::os::unix` APIs — fails to compile on Windows. `hnsw` is pure Rust, cross-platform (confirmed on x86_64-pc-windows-msvc). Requires manual URI↔ID mapping and cosine distance metric impl, but all tests pass. | 2026-03-14 |
| D007 | HNSW graph rebuilt from stored vectors on load (not serialized) | The `hnsw` crate's `Pcg64` RNG type doesn't implement serde traits, so the graph struct can't be directly serialized. Vectors + URI mappings are saved as JSON; graph is O(n log n) rebuilt on load. Acceptable at current scale. | 2026-03-14 |
| D008 | Observations use file-per-run JSONL (`<run-uuid>.jsonl`) not rolling files | Maps naturally to S03's extraction pipeline which reads "all observations for this run". Simpler than time-based rotation — no cross-file correlation needed. | 2026-03-14 |
| D009 | `ath-memory` depends on `ath-types` for agent/review/phase types | One-way dep (memory → types). `ath-types` has zero internal deps — no cycle risk. Avoids reinventing `AgentKind`, `TokenUsage`, `Severity` as parallel types in the memory crate. | 2026-03-14 |
| D010 | `ExtractionLlm` trait defined in `ath-memory`, not imported from `ath-agents` | Keeps the memory crate provider-agnostic. Downstream (S04) provides a real implementation wrapping whatever agent provider is available. Simple trait: `complete(prompt, json_schema) -> String`. | 2026-03-14 |
| D011 | Convention/agent profile merge uses append-only sections, not structural merge | Appending run-specific evidence sections is robust and predictable. Deep structural merge of markdown would be fragile and error-prone. Convention files grow monotonically across runs. | 2026-03-14 |
| D012 | `extract_all` isolates per-stage errors — failed stages don't block others | Memory extraction is best-effort post-processing. A malformed convention response shouldn't prevent run summary or decision capture. `ExtractionResult` reports success/failure per stage. | 2026-03-14 |
| D013 | Memory-aware orchestrator code lives entirely in `memory.rs` — existing phase_runner.rs untouched | Duplicates the phase execution loop with memory hooks rather than adding `Option<&MemoryContext>` to existing functions. More code, but zero risk to the 135 existing tests. The `_with_memory` entry points are additive-only. | 2026-03-14 |
| D014 | Memory-aware coordinator runs parallel groups sequentially | Observation ordering must be deterministic for extraction to produce reliable results. Parallel memory-aware execution deferred — the non-memory path retains full parallelism. | 2026-03-14 |
| D015 | Injected context uses XML wrapper format (`<athena_context>` + named section tags) | Structured format allows agents to parse sections selectively. Tags: `<project>`, `<relevant_context>`, `<agent_notes>`, `<recent_run>`. Easy to extend with new section types. | 2026-03-14 |
| D016 | Token estimation uses `word_count * 4 / 3` heuristic | Good-enough approximation for budget enforcement without requiring a tokenizer dependency. Swappable to tiktoken or similar later if precision matters. | 2026-03-14 |
| D017 | Added `serde::Deserialize` directly to `InjectionConfig` and `ExtractionConfig` | Simpler than intermediate mapping structs — no conversion layer needed. These structs only had `Debug, Clone` before. | 2026-03-14 |
| D018 | `gc` only targets `.jsonl` files in observations directory | Non-jsonl files are explicitly ignored for safety — prevents accidental deletion of index files or other artifacts placed in the observations directory. | 2026-03-14 |
| D019 | Stats uses direct filesystem walks rather than adding methods to `VikingStore` | Keeps the store API focused on read/write/list/delete. Stats needs cross-cutting info (disk usage, observation counts) that doesn't belong in the store trait. | 2026-03-14 |
| D020 | Keyword index saved after extraction regardless of per-stage success/failure | Partial keyword updates from successful stages are still valuable. Consistent with D012's per-stage isolation pattern. Save is fail-soft with `tracing::warn`. | 2026-03-14 |
| D021 | SHA-256 on `serde_json::to_string` for plan fingerprint | Deterministic because serde field order follows declaration order. Simple, no canonical JSON library needed. Same plan always produces same hash. | 2026-03-14 |
| D022 | Checkpoint save is fire-and-forget (`let _ =`) | Checkpoint persistence failure shouldn't crash the run — the run itself succeeded and its results should be returned. Worst case: user loses resumability. | 2026-03-14 |
| D023 | Stale checkpoint produces error, not silent discard | User must explicitly use `--fresh` to clear a stale checkpoint. Silent discard could lose completed work from a prior run that the user expects to resume. | 2026-03-14 |
| D024 | Checkpoint granularity is per phase group, not per individual phase | Simpler implementation, avoids partial group state. If 2 of 3 phases in a parallel group complete before the 3rd fails, the entire group is re-run on resume. | 2026-03-14 |
| D025 | `PhaseRestored` event mirrors `PhaseCompleted` field structure | Consistent progress rendering — CLI handlers treat restored phases like completed ones with different labels. | 2026-03-14 |
| D026 | `AgentId` stores provider as lowercase string, model as-is | Provider matching is case-insensitive. `AgentId::new("Anthropic", "opus-4")` normalizes to `provider: "anthropic"`. | 2026-03-14 |
| D027 | `AgentRegistry` keyed by provider string instead of enum discriminant | Extensible to any number of providers without modifying the type system. One backend per provider. | 2026-03-14 |
| D028 | Custom serde `visit_map` handles both legacy enum format and new struct format | Single deserializer detects `{"Claude":"opus-4"}` vs `{"provider":"anthropic","model":"opus-4"}` by key name. No wrapper types needed. | 2026-03-14 |
| D029 | `priority()` returns 3 for custom providers | Built-in providers keep 0/1/2 priority. Custom providers get lowest priority by default. Configurable priority deferred to S03 (skill routing config). | 2026-03-14 |
| D030 | API keys referenced by env var name in agents.toml, never as literals | Security: config files can be committed without leaking secrets. `api_key_env = "ANTHROPIC_API_KEY"` resolved at runtime via `std::env::var`. | 2026-03-14 |
| D031 | AgentsConfig defaults synthesized from ConfigStore fields | Backward compat: when no `.ath/agents.toml` exists, `default_agents_from_config()` creates entries from existing env vars + model defaults. Zero config change for existing users. | 2026-03-14 |
| D032 | Custom providers skip with warning in `build_backend_for_agent` | Unknown providers not yet supported — deferred to S04 (generic OpenAI provider). Warning printed to stderr, agent skipped, no crash. | 2026-03-14 |
| D033 | Skills config routes override defaults, don't replace entire table | Unspecified tags keep hardcoded routing. Config is additive/override, not a full replacement. Reduces required config for minor tweaks. | 2026-03-14 |
| D034 | Route tags normalized to lowercase in `SkillsConfig::parse()` | Case-insensitive matching — "Rust" and "rust" route to the same agent. Consistent with taxonomy's lowercase convention. | 2026-03-14 |
| D035 | Custom `base_url` uses OpenAI adapter kind via `ServiceTargetResolver` | All OpenAI-compatible endpoints (Ollama, Groq, Together) share the same chat completions protocol. Single adapter handles all. | 2026-03-14 |
| D036 | `GenericHandle` accepts optional API key | Ollama and other local models don't require auth. `api_key: None` skips the auth resolver entirely. | 2026-03-14 |
| D037 | JSON schema requests fall back to non-streaming `exec_chat` | Not all providers support structured output + streaming simultaneously. Safety fallback. | 2026-03-14 |
| D038 | `ChunkCallback` is `Arc<dyn Fn(&str) + Send + Sync>` | Can be cloned, sent across actor boundaries, and shared across retry attempts. | 2026-03-14 |
| D039 | `send_streaming()` has default impl delegating to `send()` | MockBackend and existing tests unchanged — streaming is opt-in. | 2026-03-14 |
| D040 | StreamChunk events only emitted when observer captures_transcripts | Avoids overhead in normal (non-verbose) mode | 2026-03-14 |
| D041 | Progress bar suspended during chunk writes via `progress_bar.suspend()` | Prevents spinner redraw interleaving with streaming text | 2026-03-14 |
| D042 | `ChatMessage` uses ~4 chars/token for estimation | Conservative heuristic, avoids tiktoken dependency | 2026-03-14 |
| D043 | Conversation truncation keeps first 2 messages + most recent, drops middle | Preserves initial context and latest state | 2026-03-14 |
| D044 | `AgentRequest.messages` has `serde(default, skip_serializing_if)` | Backward compat with existing serialized data — empty vec is default | 2026-03-14 |
| D045 | Conversation history per task keyed by task name | Each task has independent multi-turn history within a phase | 2026-03-14 |
| D046 | Records prompt+response after each task execution | History accumulates naturally across retry attempts | 2026-03-14 |
